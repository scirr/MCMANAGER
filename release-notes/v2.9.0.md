## MC Manager v2.9.0

Cross-platform Minecraft server manager. A single bilingual (FR/EN) build per
platform. The language is chosen on first launch and can be changed anytime
with `mc language fr|en`.

A content release: every common server type, modpacks, mods and plugins by
name, Minecraft upgrades, and a Java runtime managed per server. Linux only
for now; the Windows build changes only in its version number.

### New (Linux)

- **More server types.** `mc deploy` (interactive, or `--yes --loader ...`)
  now also installs Folia, Purpur, Quilt, Spigot (compiled with BuildTools,
  needs `git`), and the proxies Velocity, Waterfall and BungeeCord. Proxies
  get their port written into their own config file and are stopped with
  SIGTERM (they have no RCON).
- **`mc upgrade <version|latest>`** moves a server to another Minecraft
  version. It refuses while the server runs, for a downgrade (a world cannot
  go back) and when the loader is not published for that version; the world
  is backed up first and the previous server jar is kept.
- **Modpacks:** `mc modpack install <source> --accept-eula` creates a server
  from a Modrinth pack (`.mrpack` file, URL or slug), a CurseForge server pack
  (`curseforge:<slug>`, API key needed) or an FTB pack (`ftb:<id>`): the right
  loader and version, server-side files only, overrides, its own Java.
  `mc modpack update` moves it to the newest pack version, keeping the world
  and setting the old pack files aside. `mc modpack info <source>` describes
  a pack without installing it.
- **Mods and plugins by name:** `mc mod add <name>` installs the newest
  release built for the server's loader and Minecraft version, from Modrinth
  (mods), Hangar then Modrinth (plugins), or CurseForge (`--source curseforge`,
  API key), with its required dependencies. Client-only mods are refused;
  mods players do not need stay out of the AutoModpack modpack.
  `mc mod update [--all]` replaces them with newer versions (old files go to
  quarantine). `mc mod list` shows where each file came from.
- **Managed Java:** every server runs on the Eclipse Temurin version its
  Minecraft version requires (read from Mojang's metadata), downloaded once
  into the MC Manager folder and verified by its SHA-256. `mc java list`,
  `mc java use auto|system|<version> [server]`, `mc java install|remove`.
  The system Java is no longer needed.
- `mc config set curseforge_api_key <key>`.

### Improved

- Every download from a third-party service is checked against the hash the
  service publishes, confined to the server folder, and identified with MC
  Manager's name, version and URL.

- **Options and positionals in any order:** `mc sleep enable --after 5m
  <server>` works like `mc sleep enable <server> --after 5m`, for every
  command (Linux and Windows).
- `mc mod list --json` gives each mod's id, name, version, loader and whether
  it adds blocks, read from the jar itself (fabric.mod.json, quilt.mod.json,
  mods.toml, neoforge.mods.toml, plugin.yml, velocity-plugin.json).
  `mc mod remove` accepts a file name, an id or a display name.
- `mc datapack enable <pack> --first` now places the pack right after the
  last built-in pack, so vanilla no longer overrides it. `--before-vanilla`
  keeps Minecraft's raw "first".
- `mc deploy` proposes the next free RCON port instead of one another server
  already uses, and names the firewall it used (ufw or firewalld).

### Fixed

- Forge and Paper are installed by a single code path (`mc_software`) for the
  interactive and the `--yes` deployment: Forge from maven.minecraftforge.net
  with the recommended build (promotions_slim.json), Paper through the PaperMC
  Fill v3 API; network errors are shown instead of "no version found".
- Spigot: BuildTools runs with an explicit `-Xmx1500M`, its whole output goes
  to `<server>/logs/buildtools.log` and the `[ERROR]`, `Exception` and
  `Caused by` lines are shown. Its work folder
  (`~/.cache/mcmanager/buildtools/`) speeds up reruns but is wiped after a
  failure, since a half-finished one made the next run fail. `git` and 3 GB of
  free disk are checked first; the time limit is 45 minutes.
- Folia: a Minecraft version without a Folia build now says so and lists the
  versions that exist, instead of a generic download failure. A failed
  deployment reports its real reason in `--json`.
- AutoModpack: only `release` builds are installed and the version is shown;
  a pre-release is offered only when no release exists, and refused by default.
- The firewall step of `mc deploy` no longer says "firewalld" when ufw is the
  active firewall.
- Tests no longer depend on the ports of the machine that runs them, and the
  Windows path tests run under Windows path rules on any host.
- `mc datapack enable` now also refuses worldgen files Minecraft cannot load:
  an empty `{}` or `[]` root anywhere under `worldgen/`, and entries missing
  their required keys (`type` for structures and configured features,
  `structures` and `placement` for structure sets, `feature` for placed
  features) - such a pack made the server abort with "Failed to load
  registries".
- `mc stop` during startup no longer fails with "RCON unreachable" while the
  JVM is alive: a "Done" line left in `latest.log` by the previous run is no
  longer taken for a finished startup (the log must be newer than the process,
  which is found through its JVM when `server.pid` is not written yet), and
  when RCON still refuses the stop command the server is waited for up to
  120 s, then sent SIGTERM (Minecraft saves the world on SIGTERM). Every stop
  path (`mc stop`, the daemon's sleep and nightly stops, `mc switch`) shares
  this code.

### Updating

`mc update`. The systemd unit does not change. Existing servers keep their
current Java until `mc java use auto <server>`; new servers get their own.

### Installation
- Windows: extract the zip, then run install.bat as administrator.
- Linux: extract the zip, then run ./install.sh as root (sudo).

On the first `mc` command you will be asked to choose your language.
