## MC Manager v3.0.0

Cross-platform Minecraft server manager. A single bilingual (FR/EN) build per
platform. The language is chosen on first launch and can be changed anytime
with `mc language fr|en`.

The platform release: Linux and Windows now run the same code, with every
command available on both, and the daemon serves an HTTP API, locally and,
when you enable it, remotely over TLS. The JSON output of every command is
described by an OpenAPI 3.1 contract (`api/openapi.json`) that the test suite
checks against real `--json` runs, and failures follow one shape everywhere.

### New

- **Windows at full parity.** The Windows build is made from the same modules
  as the Linux one: sleep mode, router, mods and modpacks by name, every
  server type, managed Java, backups to sftp/S3/restic, alerts, players,
  world tools, scheduled tasks, metrics and status page. The daemon runs as
  the NSSM service `MCManagerDaemon` (downloaded on install and checked
  against a pinned SHA-256); restarting it never stops the servers. Not
  available on Windows: freezing a sleeping server (`--freeze on` answers
  `unsupported_on_windows`), cgroup and swap figures (`null`).
- **Forge and NeoForge start through java directly** on their argument files
  (`win_args.txt` is generated from `unix_args.txt` when missing), and every
  server JVM carries `-Dmcmanager.server=<folder>` so it is always found again.
- **Local API.** The daemon serves the `/v1` API on a Unix socket
  (`run/api.sock`, owner only) on Linux and on 127.0.0.1 with a token on
  Windows: 96 operations, long operations as jobs (`202` + `/v1/jobs/{id}`),
  Server-Sent Events for state changes and the console. `mc api status`.
- **Remote access, off by default.** `mc remote enable` serves the same API
  over TLS 1.3 only, with a self-signed certificate whose fingerprint the
  client pins. Devices pair with a one-time 8-digit code (`mc remote pair`)
  and get a token stored hashed; roles `viewer`, `operator`, `admin`, per
  server. Rate limits, lock-out after repeated pairing failures, audit log
  without secrets. `mc remote devices list|revoke`.
- **`mc --remote <profile> <command>`** drives a remote MC Manager: status,
  start, stop, players, logs, backup and console (`mc remote add` pairs and
  pins the certificate).
- **Linux packages.** `.deb` and `.rpm` (`/opt/mcmanager`, `/usr/bin/mc`,
  `sudo mcmanager-setup <user>`); `mc update` defers to apt/dnf on such
  installs. Removing the package never touches servers or worlds.

- **macOS.** The same core runs on macOS: the daemon is a LaunchAgent that
  never stops the servers when it restarts, processes and ports are read with
  `ps` and `lsof`, servers live in `~/Library/Application Support/MCManager`.
  The macOS firewall does not filter by port: `mc` prints the command to run.
- **Desktop apps, first release.** Linux (GTK 4 and libadwaita, also as a
  Flatpak), Windows (WinUI 3) and macOS (SwiftUI): server list with state,
  players and memory, start, stop and restart, live console and the Players
  tab (whitelist, operators, bans, kick), the Backups, Mods, Datapacks, World, Tasks and Settings tabs (sleep mode included) and a server
  creation assistant (removals and resets ask for confirmation, secret
  settings are never shown, only replaced). The
  apps talk to MC Manager only through its API, on this machine or on a
  paired remote one (pinned certificate; the device token is kept in the
  macOS keychain, encrypted with DPAPI on Windows).

### Fixed

- A `mc stop` followed by `mc resume` before the daemon's next check (30 s)
  was taken for a crash; twice in ten minutes and the server was no longer
  restarted.
- The sleep listener opened up to 5 s after the server was reported asleep;
  a player joining in between was refused.

- On Windows the API module did not load (no Unix sockets there), which
  stopped the daemon and the command line.
- On Windows the first-launch language question was asked even with `--json`
  or without a keyboard, which broke the JSON output of every script.
- Eleven documented failures of the API answered `500` instead of their
  status (kicking a player from a stopped server, for example).
- Archives are extracted with links leaving the folder, devices and absolute
  paths refused, and Python's `data` filter where available.
- Rolling back an update on Windows could fail on a file still in use.

### Changes for scripts

These changes are visible to anything that parses `--json` output or exit
codes. Every command with `--json` answers `{"schema":1,"ok":...,"code":...}`
and exits 0 on success, 1 on failure, 2 on an invalid command line and 3 when
the server is unknown.

- **`mc players --json` on a stopped server is now a failure.** It answers
  `ok:false`, `code:"server_offline"` and exits 1 (it used to answer
  `ok:true` and exit 0). `online` (0), `max` (null), `players` ([]) and
  `state` are still present. Without `--json` the command still prints an
  information line and exits 0.
- **`--json` on `mc stop`, `mc rcon`, `mc schedule`, `mc language` and `mc daemon`.**
  `stop` answers like `POST /v1/servers/{server}/stop`; `rcon` answers
  `code:"rcon_reply"` with `server`, `command` and `reply` (no ANSI codes, no `\r`),
  or fails with `server_offline` / `rcon_failed`; `schedule` answers
  `schedule_updated` (invalid times exit 2); `language` answers `language`;
  `daemon start|stop|restart|status` answers `daemon_started`, `daemon_stopped`,
  `daemon_restarted` or `daemon_status` (`installed`, `running`). `mc daemon status`
  is new.
- **Every failure has a `message`.** The text is localised (FR or EN, as chosen
  with `mc language`); branch on `code`, which is stable and never translated.
  `not_found` always carries `target` and `available` (a list of `id:name`).
- **The nested `error` object is obsolete.** `mc status`, `mc players` and
  `mc active` failures still carry `error: {code, detail}` next to the
  top-level fields for compatibility. Read `code`, `message` and `detail`
  instead; the alias will be removed in a later major version.
- **`mc config get --json`** answers
  `{"ok":true,"code":"config","server":...,"config":{...},"secrets_set":[...]}`.
  Secret settings are not in `config`; `secrets_set` lists their names.
  `mc config get <key> --json` answers `{"code":"config_value","key":...,"value":...,"write_only":false}`;
  a secret key answers `write_only:true` and no `value` unless `--reveal` is
  given. An unset key is `ok:false`, `code:"config_key_unset"`, exit 1.
  Without `--json` the output is unchanged.
- **`mc alert list --json` no longer returns `"***"`.** The `secret`, `token`
  and `password` fields of a channel are gone, not masked. `secrets_set` and
  `header_names` say what is configured.
- **`mc java list <server>`** lists only that server (exit 3 and `not_found`
  for an unknown one) instead of ignoring the argument.

### Installation

- Windows: run `MCManager-Setup.exe`. It installs everything (no Python needed),
  starts the service and adds the app to the Start menu. Servers and worlds live in
  `C:\ProgramData\MCManager` and are never touched by the uninstaller. The installer
  is not code-signed yet: Windows SmartScreen shows "Windows protected your PC";
  choose More info, then Run anyway. Without the installer: extract
  `MCManager.zip`, then run `install.bat` as administrator (needs Python 3.10+).
- Linux: `sudo apt install ./mcmanager_3.0.0_all.deb` (or `sudo dnf install
  ./mcmanager-3.0.0-1.noarch.rpm`), then `sudo mcmanager-setup <user>`. The desktop
  app (`mcmanager-app`, menu entry "MC Manager") needs GTK 4 and libadwaita:
  they are recommended packages, installed by default. Without a package:
  extract `MCManager-Linux.zip`, run `./install.sh` as root; the app is in `app/`
  (`./app/mcmanager-app`).
- macOS: extract `MCManager-macOS.zip`, run `./install.sh` as your user (not with
  sudo). For the desktop app, unzip `MCManager-App-macOS.zip` and move
  `MCManager.app` to Applications. The app is not signed: on the first launch,
  right-click it, choose Open, then confirm (or allow it in System Settings,
  Privacy & Security).

Every file is signed in `SHA256SUMS` (Ed25519, checked by `mc update`) and carries a
build provenance attestation. `mc update` only replaces the core package of its
platform; the Windows installer, the packages and the app are updated by installing
the new version.

On the first `mc` command you will be asked to choose your language.
