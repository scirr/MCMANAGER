## MC Manager v2.8.0

Cross-platform Minecraft server manager. A single bilingual (FR/EN) build per
platform. The language is chosen on first launch and can be changed anytime
with `mc language fr|en`.

A hardening release: fewer privileges everywhere, private secrets, and
checks that the RCON admin port can never be reached from outside. Linux
only; the Windows build changes only in its version number and its longer
RCON passwords.

### Improved (Linux)

- **polkit instead of sudo.** `install.sh` installs a rule that lets the
  service user start, stop and restart `mc_manager.service`, and nothing
  else. `mc daemon ...` and `mc update` go through it and never
  prompt; sudo remains only as a fallback for installations that have not
  re-run the installer.
- **Hardened systemd service**: no privilege escalation, no capabilities,
  private `/tmp` and devices, read-only system directories, protected kernel
  tunables, modules, logs and control groups, restricted socket families,
  namespaces, realtime and SUID. `MemoryDenyWriteExecute` is deliberately
  left out (the Java JIT needs it). Check with
  `systemd-analyze security mc_manager`.
- **Secrets readable by their owner only.** `config.json`, `webhooks.json`
  and `servers.json` are written `600`; `mc doctor` tightens existing files.
  A file written with `sudo mc ...` keeps its owner, so the service can
  always read it. `run/` is `700`.
- **RCON:** new servers get a 32-character password. `mc doctor` reports an
  error if a ufw/firewalld rule opens the RCON port, or if RCON listens on
  every interface while no firewall is active, and warns about passwords
  shorter than 16 characters (with the command to change it).
- **Sleep listener:** at most 4 simultaneous connections per address (32 in
  total), and a client that does not close is cut after 3 seconds instead
  of 10.
- **SECURITY.md**: how to report a vulnerability privately, and how releases
  are protected and verified.

### Behaviour changes

- `config.json`, `webhooks.json` and `servers.json` are no longer readable by
  other users. A script that reads them must run as the same user as MC
  Manager (or as root) - or, better, use `mc config get`, `mc active --json`
  and `mc status --json`.

### Updating

1. `mc update`
2. **Required on Linux:** re-run `sudo ./install.sh` from the MC Manager
   folder. It installs the hardened unit and the polkit rule; `mc update`
   and `mc doctor` report the unit as outdated until then. Servers and
   settings are kept; running servers are not stopped.
3. `mc doctor` once: it sets the permissions of existing files to `600`.

### Installation
- Windows: extract the zip, then run install.bat as administrator.
- Linux: extract the zip, then run ./install.sh as root (sudo).

On the first `mc` command you will be asked to choose your language.
