## MC Manager v2.4.9

Cross-platform Minecraft server manager. A single bilingual (FR/EN) build per
platform. The language is chosen on first launch and can be changed anytime
with `mc language fr|en`.

This is a reliability release: no new command, no change to the files you
edit. Every fix below comes from a real incident on a production server.

### Fixed

- **A UTF-8 BOM no longer stops supervision.** `servers.json`, `config.json`,
  `webhooks.json` and `language.txt` saved with a BOM (Windows editors,
  PowerShell) are read normally. An unreadable `servers.json` is no longer
  read as "no servers": the daemon keeps supervising the last known list and
  nothing overwrites the file. An unreadable `config.json` only affects its
  own server - `mc status` and `mc doctor` show the error and how to fix it.
- **No more zombie JVMs.** The daemon now reaps the servers it spawned; a
  zombie is never counted as a running server.
- **No more false "port already in use".** The start guard ignored the
  lingering TIME_WAIT sockets that delayed restarts by up to a minute.
- **A server is identified by its JVM, not by its port.** A process is only
  adopted as the server if it is `java` running in the server folder. Another
  program holding the port is shown as `port 25565 held by <program> (PID)`,
  is never adopted, and `mc stop --force` never kills it (Linux).
- **`mc stop` waits for the process to really exit** (the port is released
  before the JVM ends). Sequence: `save-all flush`, `stop`, wait up to
  `stop_timeout` (120 s), then SIGTERM, then SIGKILL - no data loss, the
  world was flushed first (Linux).
- **`config.json` is the single source of truth for ports and RCON.** On every
  start, `server-port`, `enable-rcon`, `rcon.port` and `rcon.password` in
  `server.properties` and the ports in `servers.json` are brought in line,
  and each correction is printed (Linux).
- **RCON no longer hangs** when the server closes the connection mid-reply.
- **Backups** use `save-all flush` before copying the world.
- **`mc edit`** no longer goes through a shell (paths with quotes, `$EDITOR`
  with arguments).

### Improved

- **Documented exit codes**: 0 success (or state already reached), 1 failure,
  2 invalid command line, 3 server not found, 130 interrupted.
  Previously every command returned 0.
- **No raw Python traceback** is ever shown: a one-line message, details in
  `logs/cli-error.log` (`MCMANAGER_DEBUG=1` shows the traceback).
- **Plain output when piped** (no colour codes), or with `NO_COLOR` set.
- **`mc doctor`** (Linux) now also checks: systemd unit up to date, Java
  version (warns if not 21), zombie JVMs, `config.json` readable,
  `server.properties` consistent with `config.json`, JVM started outside the
  service cgroup, JVM swap usage, and who holds a busy port.
- **`mc update`** (from the next update on) tells you when the installed
  systemd unit is older than the one this version expects.

### Behaviour changes

- `mc stop` returns once the server process has exited (a few seconds
  normally, at most `stop_timeout` + 40 s for a hung server), instead of right
  after sending `stop`.
- `mc start` on a server that is already running, and `mc stop` on a server
  that is already stopped, print an information line and exit with 0.
- Failed commands now exit with a non-zero code.

Nothing is deprecated. `servers.json` and `config.json` keep exactly the same
keys; `mode_maintenance = 1` is still the only state in which the daemon
leaves a server alone; `mc stop` / `mc resume` keep their meaning.

### Updating

`mc update`, and that's it: this release does not change the systemd unit, so
`sudo ./install.sh` is not required. If your unit is older than v2.4.x
(missing `KillMode=process`), `mc doctor` will now say so - re-run
`sudo ./install.sh` in that case.

### Installation
- Windows: extract the zip, then run install.bat as administrator.
- Linux: extract the zip, then run ./install.sh as root (sudo).

On the first `mc` command you will be asked to choose your language.
