## MC Manager v2.7.0

Cross-platform Minecraft server manager. A single bilingual (FR/EN) build per
platform. The language is chosen on first launch and can be changed anytime
with `mc language fr|en`.

This release is about trust: updates are signed and verified before anything
is installed, releases are built and signed by CI instead of on a personal
computer, and every previous release stays available for a rollback.

### New

- **Signed updates.** Every release now ships `SHA256SUMS` (hashes of both
  packages) and `SHA256SUMS.sig`, an Ed25519 signature of that file.
  `mc update` checks the signature against the public key built into MC
  Manager, then the package hash, and refuses - changing nothing, exit code
  1 - at the slightest mismatch. No new dependency: the check uses the
  `cryptography` package when it works, and a built-in implementation
  (tested against the RFC 8032 vectors) otherwise.
- **`mc update --rollback`** puts back the version installed before the last
  update (kept in `previous/`); a second `--rollback` undoes it.
- **`mc update --to <version>`** installs a specific version, older ones
  included (signed releases only, so 2.7.0 and later).
- **`mc update --check`** only checks, with `--json` for scripts.
- **ufw support** (Debian, Ubuntu) next to firewalld: the active firewall is
  detected, the game port is opened automatically (rule comment
  "MC Manager <server>"), the old rule is removed when the port changes.
  `mc doctor` checks the game port is open **and that the RCON port is not**
  (error if a rule exposes it).
- **Releases built by CI.** Pushing a tag runs the Linux and Windows test
  suites, builds both packages, signs them, records a build provenance
  attestation and publishes the release. Releases are no longer deleted:
  all versions stay available, the newest is marked *latest*.
- **Continuous integration** on every push: tests on Linux and Windows,
  `ruff`, `bandit`, `pip-audit`; Dependabot for dependencies and actions.

### Improved

- **Installer (Linux):** MC Manager now runs in its own Python environment
  (`venv/` in the application folder). Pillow is pinned to one version and
  verified by hash; the fallback installs the distribution package
  (`python3-pil` on Debian/Ubuntu, `python3-pillow` on Fedora). Every step
  reports its failures instead of hiding them. Java and Python hints now
  cover apt as well as dnf.
- `mc doctor` recognises a sleeping server whose port is held by an
  external sleep tool, and says `mc sleep enable` replaces it natively
  instead of warning about a busy port.
- Discord webhooks, downloads and updates only use https URLs.
- Service request files are no longer world-writable.
- Fixed: a signature file whose last byte looked like whitespace would have
  been misread.

### Deprecated (still working)

- Installing updates by copying files from a release ZIP by hand: use
  `mc update`, which verifies what it installs.

### Updating

This is the first signed release. **The update to v2.7.0 itself cannot be
verified**: it is installed by the previous version's updater. Every update
after it is.

1. `mc update`
2. Recommended on Linux: re-run `sudo ./install.sh` from the MC Manager
   folder, to create the Python environment and install the pinned Pillow.
   Servers and settings are kept; the systemd unit keeps the same settings.
3. `mc doctor`: on Ubuntu/Debian, the firewall lines now reflect ufw. Run it
   with `sudo` to let it read the ufw rules.

### Installation
- Windows: extract the zip, then run install.bat as administrator.
- Linux: extract the zip, then run ./install.sh as root (sudo).

On the first `mc` command you will be asked to choose your language.
