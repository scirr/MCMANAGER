## MC Manager v2.5.0

Cross-platform Minecraft server manager. A single bilingual (FR/EN) build per
platform. The language is chosen on first launch and can be changed anytime
with `mc language fr|en`.

This release makes MC Manager scriptable: explicit server states, JSON
output, and commands that spare third-party tools from reading MC Manager's
files. The new commands are Linux-only for now; the Windows build is
unchanged apart from the version number.

### New (Linux)

- **Explicit server states.** `mc status` now shows `running`, `starting`,
  `stopped`, `closed` (outside opening hours), `stopped-by-user`, `sleeping`
  or `maintenance`, plus, when running: PID, real RAM (RSS), uptime, players
  online and the next scheduled backup.
- **`mc status --json`** - the same, as JSON with a versioned schema
  (`"schema": 1`). stdout is pure JSON; errors come as `{"error": {...}}`
  with the documented exit codes.
- **`mc active [--path|--json]`** - the active server's name, folder or full
  state.
- **`mc players [--json]`** - players online. Understands vanilla ("There are
  1 of a max of 20"), Paper ("1/20") and Essentials-style replies.
- **`mc rcon "<command>"`** - run one command and print the reply; the RCON
  password is read from the config.
- **`mc config get|set <key> [value]`** - read a setting, or change it
  everywhere it lives at once: `config.json`, `servers.json`,
  `server.properties` and the firewall rule. Refuses a port already used by
  another server.
- **`mc stop --reason <user|sleep|update|maintenance|switch> [--quiet]`** -
  records why the server stopped (shown by `mc status`) and sends the
  matching Discord announcement ("sleeping", "update in progress"...);
  `--quiet` sends none. Without `--reason`, `mc stop` behaves exactly as
  before.
- **`mc freeze` / `mc thaw`** - freeze the world for an external backup
  (`save-off` + `save-all flush`). `mc freeze -- <command>` runs the command
  and always thaws afterwards, even on failure or Ctrl+C. A freeze is
  exclusive and has a deadline (`--max`, 1 h by default): if its owner dies,
  the daemon thaws the world automatically. MC Manager's own backups never
  lift a freeze they did not set.

### Improved

- Hints such as "Target: <server>" and the update notice now go to stderr,
  so command output can be piped as is.
- Four new Discord templates (`stop_sleep`, `stop_update`,
  `stop_maintenance`, `stop_switch`), added automatically to each server's
  `webhooks.json` without touching your edits.

### Deprecated (still working)

- **Reading `servers.json` / `config.json` from scripts** to find the active
  server, its folder, ports or RCON password. Use `mc active --json`,
  `mc config get <key>` and `mc rcon`. The files keep their format and keys
  (`active`, `servers.<name>.dossier_serveur`, `port`, `rcon_port`,
  `mode_maintenance`, `mcrcon_pass`, `webhook_url`, `ram_allocation`,
  `jar_name`, `loader`); they are simply no longer the recommended interface.
- **Inferring why a server is down from `mode_maintenance` alone.** Use the
  `state` field of `mc status --json`. `mode_maintenance = 1` remains the one
  switch that makes the daemon leave a server alone, and `mc stop` /
  `mc resume` keep their meaning; `stop_reason` is stored next to it.
- **Parsing the output of `list`** to count players. Use
  `mc players --json`.

### Updating

`mc update`, and that's it: this release does not change the systemd unit, so
`sudo ./install.sh` is not required. `mc update` checks the unit and says so
if it is older than expected. If you update from v2.4.8 or earlier, read the
v2.4.9 notes too: `mc stop` now waits for the process to exit, and commands
return non-zero exit codes on failure.

### Installation
- Windows: extract the zip, then run install.bat as administrator.
- Linux: extract the zip, then run ./install.sh as root (sudo).

On the first `mc` command you will be asked to choose your language.
