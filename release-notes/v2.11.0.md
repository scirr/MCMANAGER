## MC Manager v2.11.0

Cross-platform Minecraft server manager. A single bilingual (FR/EN) build per
platform. The language is chosen on first launch and can be changed anytime
with `mc language fr|en`.

A network and supervision release: a smarter sleep mode, one public port for
several servers, Prometheus metrics and a public status page. It also closes
a secrets leak and fills the gaps in the JSON output. Linux only for now; the
Windows build changes only in its version number.

Every command with `--json` answers `{"schema":1,"ok":...,"code":...}` and
exits 0 on success, 1 on failure, 2 on an invalid command line and 3 when the
server is unknown. Fields are only ever added to existing documents.

### New (Linux)

- **Advanced sleep.** `mc sleep enable --join-mode hold` keeps the connecting
  player on the line while the server wakes up, then relays the connection
  (PROXY protocol v2 for servers that support it); `--hold-timeout` bounds the
  wait. `--freeze on` suspends the JVM instead of stopping it, so waking up
  takes a moment instead of a full start. Banned IPs are refused before they
  can wake anything. `mc sleep status` shows the join mode, timeout and
  freeze setting.
- **Hostname router.** `mc router enable|disable|status`, `mc router route
  add <host> <server>` / `remove` / `list`, `mc router default <server>` and
  `mc router allow|deny add|remove <CIDR>`: several servers behind one public
  port, chosen by the hostname the player typed (FML suffixes handled).
  Connection limits per IP and per second, CIDR allow and deny lists, PROXY v2
  in and out for trusted load balancers.
- **Metrics.** `mc metrics serve [--bind HOST:PORT] [--allow-remote]` exposes
  a Prometheus endpoint (state, players, uptime, memory, TPS for Paper,
  Purpur, Forge and NeoForge). It listens on loopback unless told otherwise.
- **Status page.** `mc status-page enable|disable [--dir D] [--interval S]
  [--show-players]` keeps a static public page and `status.json` up to date;
  it holds no secret, no address and, by default, no player name.
- **JSON everywhere.** `--json` is now accepted by `mc freeze`, `mc thaw`,
  `mc doctor` (a list of checks with `name`, `ok`, `level`, `detail`, `fix`),
  `mc resume`, `mc use`, `mc remove` (needs `--yes`), `mc mode`, `mc backup`
  and `mc logs`.

### Improved

- `status`, `active`, `players`, `java list` and `sleep status` documents now
  carry `ok` and `code` at the top level (the existing `error` object stays).
- Every date in a JSON document comes with an epoch twin in seconds (UTC):
  `created_ts` for backups and bans, `join_ts` and `leave_ts` for the player
  history, `next_run_ts` and `last_run_ts` for tasks, `frozen_since_ts` and
  `frozen_expires_ts` for a frozen world.
- `mc mod list --json` keeps the version read from the jar in `version` and
  adds the one MC Manager tracks as `tracked_version`.
- Server snapshots carry `server` next to `name`, like every other result.
- `mc router disable` and `mc router route remove` give a server its public
  port back (`server-port`, empty `server-ip`) once nothing routes to it and
  it is not in hold mode, and say that a restart is needed. `route add` and
  `default` say so too, and `mc router status` lists the servers whose restart
  is pending.
- The address announced to players uses the port they really connect to (the
  router's when the server sits behind it), and a proxy binds the port the
  process listens on.

### Fixed

- **Secrets were printed.** `mc config get` showed the whole `config.json`
  (RCON password, Discord webhook, CurseForge key, alert channels, backup
  destinations). Secrets are now shown as `***` and `secrets_set` lists their
  names; `mc config get <key>` on a secret needs `--reveal` and never prints
  in JSON. `mc alert list` gives webhook header names instead of values.
  `mc backup remote list` no longer returns the S3 access key or the path of
  a key or password file, only `secrets_set`. Error messages from alerts and
  destinations are redacted too, and a test now checks every `--json` command
  against a configuration full of recognisable fake secrets.
- **A stop and a resume were taken for a crash.** A `mc stop` followed by
  `mc resume` before the daemon's next check (30 s) counted as an unexpected
  exit; twice in ten minutes and the server was no longer restarted. A stop
  that was asked for is now remembered and never counted.
- **The sleep listener opened late.** It came up to 5 s after the server was
  reported asleep, and a player joining in between was refused. It now opens
  in the same check that puts the server to sleep.
- **Windows: the service did not start from a folder with a space.** Installed
  in a path such as `C:\Users\Jean Dupont\MCManager`, the daemon service
  could not find its script because the path was not quoted. Run
  `install.bat` again after updating to repair an existing service.
- Everything fixed in v2.10.0.

### Updating

`mc update`. The systemd unit does not change. Hold mode, frozen sleep and the
router move the server to an internal port on 127.0.0.1: restart each server
once after enabling them (`mc router status` and `mc sleep status` tell you
when it is pending). Existing servers keep their configuration; the new keys
appear only once used. If you parse `mc backup remote list --json` or
`mc alert list --json`, read `secrets_set` and `header_names` instead of the
removed credential fields.

### Installation
- Windows: extract the zip, then run install.bat as administrator.
- Linux: extract the zip, then run ./install.sh as root (sudo).

On the first `mc` command you will be asked to choose your language.
