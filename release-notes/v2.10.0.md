## MC Manager v2.10.0

Cross-platform Minecraft server manager. A single bilingual (FR/EN) build per
platform. The language is chosen on first launch and can be changed anytime
with `mc language fr|en`.

An operations release: manage players and worlds from the command line,
schedule recurring tasks, restore and replicate backups, and get alerts
outside Discord. Linux only for now; the Windows build changes only in its
version number.

Every new command accepts `--json` (`{"schema":1,"ok":...,"code":...}`) and
exits 0 on success, 1 on failure, 2 on an invalid command line and 3 when the
server is unknown. All of them go through `mc_api`, the layer a network API
will use.

### New (Linux)

- **Players.** `mc whitelist add|remove|list|on|off`, `mc op add|remove|list`,
  `mc ban add|remove|list [--reason]`, `mc ban-ip add|remove|list` and
  `mc kick <player> [--reason]`. A running server is driven through RCON and
  the server's own JSON file is read back to confirm the change; a stopped
  server has `whitelist.json`, `ops.json`, `banned-players.json` and
  `banned-ips.json` edited directly and atomically. The UUID comes from the
  Mojang API, or from the offline UUID when `online-mode=false`. Names must
  match `[A-Za-z0-9_]{3,16}`.
- **`mc players history [--days N]`** lists connections and disconnections
  from `latest.log` and the `*.log.gz` files (player, join, leave, duration).
  The IP is shown only with `--show-ip` or `--json`.
- **Worlds.** `mc world list` (dimensions and size on disk),
  `mc world export [--output file.zip]` (server stopped or frozen; leaves out
  `session.lock` and Distant Horizons' `.sqlite` files),
  `mc world import <zip|folder> [--yes]` (server stopped, world backed up
  first, `level.dat` required), `mc world reset <dimension> [--yes]` (removes
  `region/`, `entities/` and `poi/` after a backup; the overworld needs
  `--include-overworld`) and `mc world pregen <radius> [--center x,z]` /
  `--status`, which drives the Chunky mod or plugin and points to
  `mc mod add chunky` when it is missing.
- **Scheduled tasks.** `mc task add --cron "<5 fields>" --action
  restart|backup|command|stop|start [--command C] [--warn 10m,5m,1m]
  [--name N]`, then `list`, `remove`, `run`, `enable` and `disable`. The
  daemon evaluates the cron expressions itself (lists, ranges, `*/n` steps,
  local time); a task missed while the daemon was down is not caught up.
  `restart` and `stop` announce the countdown in game, then stop the server
  with the new `scheduled` reason (`mc stop --reason scheduled`); `restart`
  then starts it again. `mc task list --json` gives each task's next run, last
  run and result, and every run is logged in `daemon.log`.
- **Backups.** `mc backup list`, and `mc backup restore <id|file|latest>
  [--yes]`: the server must be stopped, the current world is backed up first,
  the archive is extracted aside and swapped in, and the old world is put back
  if anything fails. `backup_keep` and `backup_retention_days` are applied
  after each backup; the newest backup is never deleted.
- **Remote backup destinations.** `mc backup remote add|remove|list|test`:
  `sftp://user@host:port/path` through the system `sftp` and a key,
  `s3://bucket/prefix` through a built-in AWS Signature V4 client (custom
  endpoint for S3-compatible services, nothing but the standard library), and
  `restic:<repository>` when restic is installed. With
  `backup_encrypt_key_file` set, archives sent to sftp or S3 are encrypted
  with `openssl enc -aes-256-cbc -pbkdf2` (unencrypted with a warning when
  openssl is missing). A failing destination is reported but never cancels the
  local backup. The world is frozen while it is copied.
- **Alerts.** `mc alert add email|telegram|ntfy|webhook|discord`, `list`,
  `remove` and `test`. E-mail uses SMTP with STARTTLS; the generic webhook can
  carry an HMAC signature. Events: start, stop (with its reason), crash,
  crash_loop, backup_failed, update, sleep, wake; each channel picks the ones
  it wants. Secrets are stored in `config.json` (always `600`) and masked in
  listings. A scheduled stop is announced (Discord and alerts) even though the
  scheduler raises the maintenance flag beforehand.
- `mc config set backup_keep|backup_retention_days|backup_encrypt_key_file`.

### Improved

- The player, world and task functions are available in `mc_api` next to the
  backup and alert ones, so the command line and any future front end share
  one code path.

### Fixed

- Everything fixed in v2.9.0, including `mc stop` during startup and the
  stricter datapack worldgen checks.

### Updating

`mc update`. The systemd unit does not change. Existing servers keep their
configuration; the `tasks`, `alerts` and `backup_remotes` keys appear in
`config.json` only once used.

### Installation
- Windows: extract the zip, then run install.bat as administrator.
- Linux: extract the zip, then run ./install.sh as root (sudo).

On the first `mc` command you will be asked to choose your language.
